## 39.1 Encryption and certificate management

AWS provides three core services for protecting data and communications:

| Service | Purpose |
|---------|---------|
| **KMS** | Encryption key management |
| **Secrets Manager** | Secret storage and rotation |
| **ACM** | TLS/SSL certificate provisioning |

Understanding when to use each—and how they integrate—is essential for a secure AWS architecture.

---

## 39.2 AWS Key Management Service (KMS)

**KMS** creates and manages encryption keys used to encrypt data across AWS services.

### Key types

| Type | Description | Use case |
|------|-------------|----------|
| **AWS managed** | Created and managed by AWS per service | Default S3, EBS encryption |
| **Customer managed (CMK)** | You create and control | Cross-service, custom policies |
| **AWS owned** | Shared across accounts; you cannot view | Some default encryption |
| **External (BYOK)** | Import your own key material | Regulatory requirements |

### Key concepts

| Concept | Description |
|---------|-------------|
| **CMK** | Customer Master Key — never leaves KMS |
| **Data key** | Symmetric key generated by CMK; used to encrypt data |
| **Envelope encryption** | Encrypt data with data key; encrypt data key with CMK |
| **Key policy** | Resource policy controlling key access |
| **Grant** | Delegated permission to use a key |
| **Alias** | Friendly name for a key (`alias/app-secrets`) |

### Creating a CMK

```bash
aws kms create-key \
  --description "Application encryption key" \
  --key-usage ENCRYPT_DECRYPT \
  --origin AWS_KMS

aws kms create-alias \
  --alias-name alias/app-encryption \
  --target-key-id <key-id>
```

### Terraform

```hcl
resource "aws_kms_key" "app" {
  description             = "Application encryption key"
  deletion_window_in_days = 30
  enable_key_rotation     = true

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "Enable IAM policies"
        Effect = "Allow"
        Principal = { AWS = "arn:aws:iam::123456789012:root" }
        Action   = "kms:*"
        Resource = "*"
      },
      {
        Sid    = "Allow service use"
        Effect = "Allow"
        Principal = { Service = ["s3.amazonaws.com", "rds.amazonaws.com"] }
        Action = ["kms:Encrypt", "kms:Decrypt", "kms:GenerateDataKey*"]
        Resource = "*"
      }
    ]
  })
}

resource "aws_kms_alias" "app" {
  name          = "alias/app-encryption"
  target_key_id = aws_kms_key.app.key_id
}
```

### Envelope encryption

```python
import boto3

kms = boto3.client("kms")

# Generate a data key
response = kms.generate_data_key(KeyId="alias/app-encryption", KeySpec="AES_256")
plaintext_key = response["Plaintext"]      # use to encrypt data
encrypted_key = response["CiphertextBlob"]  # store alongside encrypted data

# Decrypt the data key when needed
decrypted = kms.decrypt(CiphertextBlob=encrypted_key)
plaintext_key = decrypted["Plaintext"]
```

### Multi-Region Keys (MRK)

Replicate keys across regions for DR without re-encrypting data:

```
Primary key (us-east-1) ←→ Replica key (eu-west-1)
Same key ID, same key material, regional endpoints
```

## 39.3 AWS Secrets Manager

**Secrets Manager** stores and rotates secrets (database credentials, API keys, tokens):

### Features

| Feature | Description |
|---------|-------------|
| **Automatic rotation** | Lambda-based rotation on a schedule |
| **Cross-account access** | Resource policies for sharing |
| **Versioning** | AWSCURRENT and AWSPENDING versions during rotation |
| **Integration** | RDS, Redshift, DocumentDB native integration |

### Creating a secret

```bash
aws secretsmanager create-secret \
  --name app/prod/database \
  --description "Production database credentials" \
  --secret-string '{"username":"admin","password":"initial-password","host":"mydb.abc.rds.amazonaws.com","port":5432}'

# Enable rotation (every 30 days)
aws secretsmanager rotate-secret \
  --secret-id app/prod/database \
  --rotation-lambda-arn arn:aws:lambda:us-east-1:123456789012:function:SecretsManagerRDSPostgreSQLRotation \
  --rotation-rules AutomaticallyAfterDays=30
```

### Terraform

```hcl
resource "aws_secretsmanager_secret" "db" {
  name       = "app/${var.environment}/database"
  kms_key_id = aws_kms_key.secrets.arn
}

resource "aws_secretsmanager_secret_version" "db" {
  secret_id = aws_secretsmanager_secret.db.id
  secret_string = jsonencode({
    username = "admin"
    password = random_password.db.result
    host     = aws_rds_cluster.main.endpoint
    port     = 5432
    engine   = "postgres"
  })
}

resource "aws_secretsmanager_secret_rotation" "db" {
  secret_id           = aws_secretsmanager_secret.db.id
  rotation_lambda_arn = aws_lambda_function.rotation.arn
  rotation_rules {
    automatically_after_days = 30
  }
}
```

### Retrieving secrets in applications

```python
import boto3, json

client = boto3.client("secretsmanager")
response = client.get_secret_value(SecretId="app/prod/database")
secret = json.loads(response["SecretString"])
# secret["username"], secret["password"], secret["host"]
```

## 39.4 AWS Certificate Manager (ACM)

**ACM** provisions, manages, and renews TLS/SSL certificates for free:

| Feature | Detail |
|---------|--------|
| **Cost** | Free for use with AWS services |
| **Validation** | DNS (recommended) or email |
| **Renewal** | Automatic |
| **Integration** | ALB, CloudFront, API Gateway, NLB |
| **Private CA** | ACM Private CA for internal certificates ($400/month per CA) |

### Requesting a certificate

```bash
aws acm request-certificate \
  --domain-name "*.example.com" \
  --subject-alternative-names "example.com" \
  --validation-method DNS
```

### DNS validation (Terraform)

```hcl
resource "aws_acm_certificate" "app" {
  domain_name               = "app.example.com"
  subject_alternative_names = ["*.app.example.com"]
  validation_method         = "DNS"

  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_route53_record" "cert_validation" {
  for_each = {
    for dvo in aws_acm_certificate.app.domain_validation_options : dvo.domain_name => {
      name   = dvo.resource_record_name
      record = dvo.resource_record_value
      type   = dvo.resource_record_type
    }
  }
  zone_id = aws_route53_zone.main.zone_id
  name    = each.value.name
  type    = each.value.type
  records = [each.value.record]
  ttl     = 60
}

resource "aws_acm_certificate_validation" "app" {
  certificate_arn         = aws_acm_certificate.app.arn
  validation_record_fqdns   = [for record in aws_route53_record.cert_validation : record.fqdn]
}
```

### Certificate limitations

| Limitation | Detail |
|------------|--------|
| **Export** | Cannot export private keys (use with AWS services only) |
| **Region** | CloudFront requires certificates in us-east-1 |
| **Wildcard** | `*.example.com` covers one level only |
| **On EC2** | Cannot install ACM certs directly; use ALB/CloudFront or import |

## 39.5 Choosing the right service

| Need | Service |
|------|---------|
| Encrypt EBS, S3, RDS at rest | KMS |
| Store database password with rotation | Secrets Manager |
| Store API key (no rotation) | Parameter Store (SecureString) or Secrets Manager |
| TLS for ALB/CloudFront | ACM |
| Internal mTLS certificates | ACM Private CA |
| Application-level encryption | KMS envelope encryption |

## 39.6 Security best practices

| Practice | Rationale |
|----------|-----------|
| Use customer managed CMKs | Control key policies, enable rotation, audit usage |
| Enable automatic key rotation | Annual rotation of CMK material |
| Separate keys per environment | Limit blast radius |
| Use Secrets Manager for rotating credentials | Automatic rotation reduces exposure window |
| DNS validation for ACM | More reliable than email validation |
| Monitor KMS API calls in CloudTrail | Detect unauthorized key usage |
| Least-privilege key policies | Grant only required principals and actions |

### CloudTrail KMS events to monitor

- `Decrypt` — unauthorized data access attempts
- `DisableKey` / `ScheduleKeyDeletion` — potential sabotage
- `PutKeyPolicy` — policy tampering

## 39.7 Chapter summary

- **KMS** manages encryption keys; use **customer managed CMKs** with automatic rotation.
- **Secrets Manager** stores and rotates credentials; integrates with RDS and Lambda.
- **ACM** provides free TLS certificates with automatic renewal for AWS services.
- Use **envelope encryption** for application-level data protection.
- Monitor key usage via **CloudTrail** and enforce **least-privilege key policies**.
